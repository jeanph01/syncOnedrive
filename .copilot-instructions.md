## Project

PowerShell-based OneDrive management suite using Microsoft Graph API for:

- **Indexing & sync:** Cloud indexing with delta sync
- **Organization:** Media classification & naming
- **Cleanup:** Duplicate detection & cleanup
- **GPS:** Reverse geocoding & GPS validation
- **Reliability:** Structured logging, error handling, and state tracking

---

## Architecture & Constraints

- **Modular:** Keep logic in dedicated modules (`AppConfig`, `OneDriveTools`, `OneDriveCacheUtils`, `OneDriveOrganize`, `GpsTools`).
- **Config-driven:** All business rules/settings in `config.ini` and `rules.json` (no hardcoded rules).
- **State:** Use `$Global:State`, `$Global:Rules`, `$Global:Config` as the only shared globals.
- **PS 5.1 compatible:** No `??`, no `ConvertFrom-Json -AsHashtable`, no newer syntax.
- **File layout:** Scripts = entry points; Modules = reusable logic; Config = ini/json; `_cache` for runtime artifacts.

---

## Coding Standards

- **Naming:**
  - Functions: `PascalCase` (`Get-SmartCategory`, `Write-Log`)
  - Variables: `camelCase`
  - Globals: `$Global:*` as above
- **Logging:** Always use
  ```powershell
  Write-Log "Message" "LEVEL"  # DEBUG, INFO, WARN, ERROR, SUCCESS
  ```
  Include meaningful messages; assume timestamping/formatting handled by `Write-Log`.
- **Error handling:**
  - Wrap risky operations in `try { } catch { }`.
  - In `catch`, log via `Write-Log ... "ERROR"` and rethrow unless there is a clear recovery path.
- **Parameters:** Use `[Parameter(Mandatory = $true)]` with validation where appropriate.

---

## Key Patterns

- **Module load guard:**
  ```powershell
  if ($script:ModuleLoaded) { return }
  $script:ModuleLoaded = $true
  ```
- **State structure (do not change shape lightly):**
  ```powershell
  $Global:State = @{
      Cache          = @{}
      FilesToProcess = @{}
      ProcessedIds   = @{}
      PlannedActions = @()
      Headers        = @{}
  }
  ```
- **Config access:** Always read rules/settings from `$Global:Rules` and `$Global:Config`, not literals.
- **Paths:** Use `Resolve-Path` and `Join-Path`; support absolute and relative paths.
- **API resilience:** Respect throttling, use retries with backoff, refresh tokens on 401, recover delta tokens when corrupted.
- **Progress:** Use `Write-Progress` for long-running loops.

---

## Smart Features & Behavior

- **Classification:** Extension-based categorization, path-based rules, GPS validation, safe naming (length limits, markers).
- **Performance:** Lazy GPS cache, incremental processing via `ProcessedIds`, batch Graph calls, streaming for large caches.
- **Debugging:** Support `-ProcessRange` for small subsets, detailed logs, plan validation, resume via cached plans.

---

## Development Rules for Copilot

When generating or modifying code for this project:

1. **Preserve modular architecture** and external configuration (no new hardcoded rules).
2. **Follow logging and error patterns** consistently; no silent failures.
3. **Update `$Global:State` deliberately** and keep its structure stable.
4. **Prefer small, testable changes**; support `-ProcessRange` for validation.
5. **Consider edge cases:** empty caches, network failures, permission issues, long paths.

Use this as the only context for syncOnedrive-related suggestions.
